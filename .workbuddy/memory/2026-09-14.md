## 排查「main.py 跑完 0 页 0 记录」（队列去重空跑）
- **现象**：`python main.py` 输出 `请求=1/1 成功、处理页数=0、线索=0、耗时 0.3s`。浏览器模式 0.3s 跑完本身就不合理。

## 14:40 真正解决"爬太快被 GS 封" —— 自研 crawl-delay 节奏控制

- **根因（此前一直没找到的真凶）**：Global Sources 的 robots.txt 对具名爬虫声明 **Crawl-delay: 10~20 秒**（voyager/facebookexternalhit=10；bingbot/Applebot/Baiduspider/GPTBot/ChatGPT-User/Claude-User/DeepSeekBot 等=20；`*` 组**未声明**）。而我们的实际速率是 `max_tasks_per_minute=100`（≈1.67 请求/秒）——**比站点声明的容忍度快约 17 倍**，所以被 429/403 连续拒绝。
- **为什么保护没生效**：crawlee 只在 `self._request_manager` 是 `ThrottlingRequestManager` 时才把 crawl-delay 交给它执行（`_basic_crawler.py:708`），否则只打一条"不会被强制执行"的提示；而该项目因 ThrottlingRequestManager 会提前结束动态入队、与 keep_alive 组合挂死而**关闭**了它 → 这条保护实际没人执行。
- **修复（自研，不依赖那个有 bug 的组件）**：
  1. `utils/robots.py` 新增 `parse_crawl_delays()`（返回 通配组值 / 文件内最小值）与 `RobotsChecker.crawl_delay()`、`resolve_crawl_delay()`。通配组为空时用"站点对具名爬虫声明过的最小值"作为容忍度下界（GS→10s）。
  2. `EngineConfig`：`min_request_interval` 1.2→**3.0**；新增 `respect_crawl_delay=True`、`max_crawl_delay`、运行期 `request_interval`；`effective_interval()`；**`effective_rate_per_minute()` 不再 ×并发**（原来 60/间隔×并发，把 crawl-delay 语义放大成 N 倍——这是速率失控的算术根源）。新增 `session_max_rotations=1`。
  3. `CrawlerRunner.resolve_pacing(config, urls)`：构建 crawler **之前**解析 robots 并写入 `request_interval`；两条 run 路径 + `ApiTemplateRunner.replay` + `discover_api`（经 CrawlerRunner.run）都已接入。
  4. `build_pacing_limiter()`（middleware）+ `build_pre_navigation_hook(config, limiter)`（browser）：导航前 `acquire()`，使"相邻请求间隔"成为硬约束，**对 429 后的重试同样生效**（重试会重新走 pre_navigation_hook）。
  5. `build_crawlee_middleware_kwargs` 注入 `max_session_rotations`。
  6. `_ensure_services()` + `_CrawleeNoiseFilter`：显式创建全局 Configuration/EventManager，并屏蔽两条已过时/误导的 crawlee 提示（crawl-delay 不会被强制执行、Implicit creation）。注意 logging 坑：filter 必须挂到 logger 本身/其 handler/`logging.lastResort`（utils.logger 用 `jjkk` logger 且 propagate=False，crawlee 记录落到 lastResort）。
- **实测证据**（本地 mock 站 + 活体 robots.txt）：GS crawl-delay 解析=**10.0s**；resolve_pacing 后 3.0s→10.0s（100/min→**6/min**）；浏览器钩子 4 并发间隔 [1.004,1.006,0.997]（限速 1.0s）；http 模式服务端实测相邻间隔 [1.009,1.008,1.012]；**429 时单 URL 命中服务端 3 次（max_session_rotations=10 的对照为 12 次，降到 25%）**；噪声告警 0 条而真实 429 告警保留；`--selfcheck` error=0、能力接线 9/9。
- **新增 CLI**：`--interval SECONDS`、`--no-crawl-delay`（main.py 与引擎 CLI 都有）。
- 未解决/待用户处理：**本机内存极紧（总 7.69GB，可用曾低至 0.4GB、系统已用 94%）**，浏览器模式仍可能被系统压死 Chrome；建议先关程序再跑，必要时 `--concurrency 1`。GS 检索页确认必须走 JS（原始 HTML 59,899B、`homepage_` 链接 0），无法改纯 http；要彻底摆脱浏览器需 `--discover` 摸出 XHR 接口后走 HTTP 重放。
