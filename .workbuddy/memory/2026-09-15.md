## 23:05 修复 run_mvp.py 崩溃（CDP 端口假阳性）+ 端到端跑通

- **用户报错**：`run_mvp.py` → `connect_over_cdp` 报 `Unexpected status 404 ... This does not look like a DevTools server`。
- **根因（两层）**：
  1. `core/browser.py::ensure_chrome_running` 用 `is_port_open()`（端口能连上）判断"Chrome 已就绪"。而本机 **9222 端口被一个非 DevTools 的服务占着**（实测 /json/version、/json、/ 全部 404 空响应；占用进程是用户的日常 Chrome 主进程 PID 22816，父进程 explorer.exe，cmdline 读不到参数——推断为高权限启动或其它程序监听）。端口开着 → 判为就绪 → 直接 connect_over_cdp 一个假 DevTools → 404。
  2. 端口开放 ≠ DevTools 可用，这个判据本身是错的。
- **修复（`core/browser.py` 重写 + `core/base_crawler.py` 一行）**：
  - 新增 `query_devtools(port)`（GET /json/version，200 且含 Browser 字段才算可用，用标准库 urllib，404/连接拒绝统一视为"不是 DevTools"）、`is_devtools_ready(port)`、`find_available_port(start)`。
  - `ensure_chrome_running()` 现在**返回实际使用的端口**，逻辑：① 目标端口是真 DevTools → 复用；② 否则在 port+1..port+10 扫描**已有的真 DevTools 并复用**；③ 目标端口被非 DevTools 占用 → 自动改用空闲端口；④ 都没有 → 用 `--user-data-dir` 独立 profile 拉起 Chrome，就绪判据换成 `is_devtools_ready`。
  - `BaseCrawler.ensure_chrome_running()` 把返回值**回写 `self.cdp_port`**（pipeline 天眼查阶段也用 `crawler.cdp_port`，不回写会连错端口）。**pipeline.py 未改动**（遵守禁改约定）。
  - 踩到的坑：Chrome 对同一 `user-data-dir` 只允许一个实例，盲目再起一个会"启动成功但立刻退出"、端口永远等不到 DevTools。所以必须先扫描复用已有实例，而不是直接新起。

  - httpx 直连 → `SSL UNEXPECTED_EOF_WHILE_READING`（TLS 层被断）
  - Playwright **headless=new** Chrome → GS 返回 **403**（CloudFront "request could not be satisfied"）
  - 项目启动的**有头** Chrome（`ensure_chrome_running` 不加 headless）→ **完全正常抓取**
  - 所以不需要代理；GS 是"反无头"。以后排查 GS 可达性必须用有头浏览器，用 headless 会得到误导性 403。
